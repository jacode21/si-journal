Google DeepMind Used AI Agents to Prove Signal’s Encryption Code Correct

Google DeepMind said on Tuesday, November 10 that its AlphaProof Code system — a team of AI agents guided by human security experts — produced machine-checked mathematical proofs that key security properties hold in Signal’s deployed encryption code, down to the compiled program that runs on phones. The agents generated more than six million lines of proof in Lean, the proof language a computer can verify step by step, in four weeks. DeepMind has published the proofs and its technical paper for anyone to inspect.
Edited by Avery Lane · Frontier Editor  ·  Issue No. 024  ·  Wednesday, November 11, 2026

Most software security is sampling. Testers try inputs, reviewers read code, and everyone hopes the cases they missed are the harmless ones. Formal verification is the other approach: state exactly what must always be true, then prove it, with a computer checking every step of the proof. It is strong and it is slow — verifying a real program has historically taken specialist teams years, and it usually stops at the design, not at the code that actually ships.

What was proved, and what was not

DeepMind’s target was libsignal, the encryption library at the centre of the Signal messaging app, in the exact form it runs: an executable program built without changes from libsignal version 0.105.4, together with a component called SPQR version 1.6.0. Human experts wrote and reviewed the security statements — the precise claims to be proved, covering properties of the PQXDH key agreement and the Triple Ratchet, the mechanisms that keep messages protected if a device is temporarily compromised. The agents then produced the proofs: more than six million lines of Lean in total — about 6.5 million by the technical paper’s count — and a proof checker, not the models, decided whether each argument holds. The system sent roughly one percent of the code to humans for a second look and machine-checked the rest. The whole exercise took four weeks.

The limits are part of the result, and DeepMind states them plainly. The proofs cover the named properties of the named components. Group messaging sits outside the verified scope. Nothing here shows that the whole Signal app is free of vulnerabilities, and a proof is only as good as the statement it proves: a correct proof of an incomplete requirement is still incomplete security.

The test that makes it evidence

The strongest part of the work is a deliberate failure. DeepMind reintroduced two previously fixed vulnerabilities into an isolated copy of the code and ran the system again. AlphaProof Code rejected both versions and produced machine-checked proofs that the buggy builds violated the intended properties. A system that only ever says “correct” proves nothing; this one was shown catching the errors it was built to catch. DeepMind has open-sourced the verification artefacts and the technical paper, so outside researchers can inspect the statements, the assumptions and the coverage rather than take the announcement on trust.

The timing is not subtle. On Friday this paper reported DeepMind agents finding weaknesses in retired 1024-bit encryption — AI used to attack old cryptography. On Tuesday the same lab published AI used to defend current cryptography, at a standard of evidence the attacking work does not claim. The two stories share a mechanism, agents that work for weeks on formal problems, and differ in the one property that matters here: the defence arrives with proofs a sceptic can re-run.

The Bigger Picture

Verification changes what a lab has to show. A benchmark score asks to be believed; a machine-checked proof asks to be re-run, and the checker does not work for the lab. If the method holds up under outside scrutiny, the procurement question for safety-critical software — in payments, in firmware, in messaging — shifts from “who reviewed this?” to “where is the artefact, and what exactly does it cover?” The coverage question is the honest one, and it is the one today’s announcement teaches readers to ask.
